## 0. 一句话概念（Pitch）

> 你是一位在多元文化小镇开餐馆的厨师：亲手用**节奏与火候**把食材“调”成客人想要的味道，再把一间小店经营成遍布世界的饮食帝国——同时小心那些**不该端上桌的菜**。

**三条设计支柱**（任何新功能都应至少强化其中一条，否则砍掉）：

| 支柱               | 一句话                      | 主要承载系统           |
| ---------------- | ------------------------ | ---------------- |
| **手艺 Handcraft** | 做菜手感：节奏、火候、分心调度          | QTE 工序、双菜并发、处理反应 |
| **创造 Creation**  | 用五维（口味/温度/香味/口感/完成度）自由搭配 | 口味矩阵、处理链、自建食谱    |
| **经营 Empire**    | 从一间店到全世界分店               | 定价、人气、雇人、分店、声望   |

        │               ▲                     │                                    │

  中期循环：攒钱+声望 ──► 解锁新地点 ──► 开分店(装修/菜谱/雇人) ──► 多店收益

```
接单队列 ─► 玩家自由排序工序 ─► 每个工序弹出对应 QTE ─► 调整口味/温度 ─► 摆盘 ─► 交付 → 客人打分
```

## 3. 战斗核心：一盘菜的五维模型

这是整个游戏最关键的**数据模型**。做菜的一切系统最终都在修改这五项属性。

| 维度                 | 类型     | 来源                | 作用               |
| ------------------ | ------ | ----------------- | ---------------- |
| **口味 Flavor**      | 7×4 矩阵 | 食材 + 处理 + 调味      | 主导味/复合味判定，客人期待匹配 |
| **温度 Temp**        | 标量 ℃   | 加热 + 时间 + 环境      | 放大/抑制不同味道        |
| **香味 Aroma**       | 标签集合   | 调味类食材 + 化学反应      | 综合加成；缺失重罚        |
| **口感 Texture**     | 3 条对立轴 | 主要食材 + 处理方式       | 与食谱/客人口感要求匹配     |
| **完成度 Completion** | 0–100  | QTE 表现            | 基础品质分            |
| **搭配度 Harmony**    | 0–100  | 口味/香味/口感组合 + 特殊处理 | 组合品质分            |

> **重要解耦原则**：一盘菜的**物理属性**（上面 6 项）由做菜系统产生；
> **评分**不由做菜系统决定，而是由“客人系统”拿物理属性去**对比客人的期待**后计算。
> 这样同一盘菜给不同客人效果不同，也让所有评分逻辑集中在客人侧，便于调平衡。

### 3.1 口味矩阵（Flavor Matrix）

**结构：7 基础味 × 4 时序槽 = 28 维向量**（原作的“2×2×7”即：前/余 × 主/回 × 7 味）。

- **7 基础味**：酸、甜、苦、辣、咸、鲜、麻
- **4 时序槽**：
  - **前味**（入口第一感）
  - **主味**（咀嚼时的核心味）
  - **余味**（咽下后残留味）
  - **回味**（鼻腔/后段回香）
  - （原作用“前味-主味-甜味”举例，即 `矩阵[甜][前味]`）

**派生概念**：

- **主导味**：主味槽中强度最高的味（如“甜口”）。
- **复合味**：主味槽中第二个强度超过阈值 `θ_compound` 的味（如“鲜甜口”）。**复合味不覆盖主导味**，仅作描述标签与加成。
- **[建议值]** `θ_compound = 40`（强度 0–100）。

**强度**：每格 0–100，代表该味在该时序的突出度。

### 3.2 口感矩阵（Texture）

三条**对立轴**，各取 −1 ~ +1（负端 / 正端）：

| 轴   | 负端 (−1) | 正端 (+1) |
| --- | ------- | ------- |
| A   | 硬       | 嫩       |
| B   | 韧       | 脆       |
| C   | 弹       | 粘       |

- 食材有**天然基准值**：如牛肉韧性极高（B ≈ −0.8），黄瓜韧性极低（B ≈ +0.2）；馒头可做成弹（C ≈ −0.5）或粘（C ≈ +0.5）。
- **处理方式**平移/压缩这些轴：加热→嫩化（A 向 +1）；长时间加热→脆度下降等。具体由“处理反应表”定义（见 §4.2）。
- 食谱/客人可对某条轴提要求（如“鸡蛋要嫩”→ A ≥ +0.5；“西红柿切大块”→ 细碎度 ≤ 阈值）。

### 3.3 香味（Aroma）

**独立标签集合**，每个标签带强度。缺香 → 严重减成。

| 标签      | 来源        | 效果          |
| ------- | --------- | ----------- |
| 花果香     | 茶/花/果类调味  | 综合提升完成度与搭配度 |
| 焦糖香     | 焦糖化反应     | 同上          |
| 肉香      | 美拉德（肉+糖）  | 同上          |
| 坚果香     | 美拉德（坚果+糖） | 同上          |
| 复杂香气    | 发酵        | 同上，强度高      |
| 陈旧地沟油气息 | 脂肪氧化      | **负向**，降分   |

> **[建议值]** 勾选：无任何香味 → 完成度 ×0.7、搭配度 −15；命中食谱期待香型 → 搭配度 +10。

### 3.4 温度（Temp）

标量，单位 ℃。**双向影响**

**随时间的自然衰减**：

```
T(t) = T_room + (T₀ − T_room) · e^(−t/τ)
```

- `T_room` [建议值] 22℃，`τ` [建议值] 90 秒（普通容器）。
- **恒温箱**道具：令 `τ → ∞`（温度锁定），适合需要精确控温的高端菜。

**温度对口味的作用表**：

| 区间         | 被放大的味        | 被抑制的味 | 时序影响 |
| ---------- | ------------ | ----- | ---- |
| 低温（< 40℃）  | 酸 ↑↑、苦 ↑     | 鲜/辣/麻 | 余味 ↑ |
| 适中（40–65℃） | 咸 ↑↑、甜 ↑↑    | —     | 平衡   |
| 高温（> 65℃）  | 鲜 ↑↑、辣 ↑、麻 ↑ | 酸     | 前味 ↑ |

### 3.5 食材数据模型

```
Ingredient {
  id, name
  category:   大类（如 醋、酱油、糖、肉类…）
  subcategory:小类（如 山西醋/广东醋/苹果醋）
  quality:    品质等级
  baseFlavor: float[7]           // 基础味强度
  baseTexture:{A, B, C}          // 天然口感轴
  aromaTags:  [enum]             // 自带香味
  regionTag:  地域/文化标签（如 广式、川式）
  specialProps: 特殊效果（见下）
}
```

- **大类可互相替换**：同一大类下任何小类都能补位，但**效果不同**。
- **小类差异示例**：
  - 山西醋：比一般醋**更酸更甜**（baseFlavor 酸 +、甜 +）。
  - 广东醋 + 广东酱油 → 可做出“地道的”**广式肠粉**：搭配度加成 + 对同文化顾客额外加成。
- **调味类食材**（海鲜酱油/花椒大料/茶/花等）→ 主要产出**香味标签**。
- **品质**：优品可**解锁或更容易打出 perfect QTE**，并给完成度小幅加成 [建议值 +5]。

### 3.6 食谱（Recipe）

```
Recipe {
  requiredIngredients: [{ id, minFine, maxFine }]   // 必需食材 + 细碎度约束
  requiredSteps:       [工序枚举]                    // 如 [切块, 炒]
  idealFlavorWindow:   { [味][时序]: [min, max] }     // 理想口味区间
  idealTempRange:      [min, max]
  idealTexture:        { A?, B?, C? }                // 口感要求
  idealAroma:          [enum]                        // 期待香型
  isOfficial / isCustom
}
```

**规则**：

1. 食谱定义**理想口味区间**、**必需基本食材**与**必需工序**。
   - 例：甜西红柿炒鸡蛋 → 前味必须酸甜口，余味必须甜口；**必须**有西红柿 + 鸡蛋；西红柿**必须切块**；**必须**有“炒”。
2. **允许加料/加工序**，但**每增加一次额外工序或食材 → 完成度 −[建议值 3]**。
3. **缺失必需项 → 严重减成**：[建议值] 完成度 ×0.4，并可能直接判为“不成菜”。
4. **自建食谱**：满足条件（口味区间 & 地道材料 & 工序）可**解锁为预设食谱**；也可直接使用自建食谱，但**加成有限**（[建议值] 自建食谱的完成度上限 ×0.9）。
5. 食谱出现在**菜谱**上 → 客人按菜谱点单；**开分店时可把自建菜谱带过去**。

### 3.7 客人评分系统（在做菜系统之外）

**输入**：菜品物理属性 `(完成度 Q, 搭配度 H, 口味矩阵, 温度, 口感, 香味)`
**对比对象**：客人在点单时**声明的要求**（未声明的维度不扣分）。

**偏差惩罚**：

```
D = Σ over 声明维度 w_dim · |期望 − 实际|  （各维归一到 0–100 后再加权）
```

[建议值] 权重：口味 0.5、温度 0.2、口感 0.2、香味 0.1。

**满意度**：

```
Satisfaction = clamp(0.35·Q + 0.25·H + 0.40·(100 − D), 0, 100)
```

**星级**：按满意度分档 → 1–5 星，决定小费、声望增减、NPC 情绪。
**小费** = `Satisfaction × 客人消费水准系数`。

## 4. 处理食材：把食材“改写”成菜品

每个工序 = 一个对菜品属性的 **modifier（效果器）**，按玩家排序顺序**顺序应用**。这种“效果器栈”模型便于数据驱动与扩展。

### 4.1 切菜（节奏玩法）

- 按 8 拍播放 BGM，**卡上节奏切菜**完成度高。
- 切菜粒度从**最细（每半拍切一次）到最粗（八拍切一次）**。
- **视觉**：刀从右到左经过，按**空格**切下，食材像素分开。
- **旋转食材**决定切型：
  - 切 1 次 = **片**
  - 切 2 次 = **块 / 条**
  - 切 3 次 = **丁**
- **细碎度 fine** 随每次切割累加：
  - fine 高 → 该食材**口味突出**：**前味大幅增强 ↑↑**，**余味小幅增强 ↑**。
  - fine 需与食谱要求匹配（如“大块”要求 fine ≤ 阈值）。

### 4.2 加热（温度 × 时间 + 化学反应）

**基础趋势**：

- 温度 ↑ → **苦、鲜、甜增强**，**酸减弱**
- 时间 ↑ → **前味减弱**，**余味增强**

**化学反应表**（条件 → 口味/香味变化）：

| 反应        | 触发条件            | 口味变化             | 香味              |
| --------- | --------------- | ---------------- | --------------- |
| **美拉德**   | 肉类/坚果 + 糖，中高温   | 鲜 ++、甜 +、苦 +、酸 − | 肉香 / 坚果香        |
| **焦糖化**   | 糖，高温            | 苦 ++、甜 −         | 焦糖香             |
| **蛋白质水解** | 肉类/坚果，中高温煮      | 鲜 ++、苦 +         | 无               |
| **脂肪氧化**  | 油/肉/坚果，高温 + 长时间 | 苦 +++、酸 ++       | 陈旧地沟油气息（**负向**） |

### 4.3 QTE 类型表

| QTE 类型  | 操作         | 对应工序      |
| ------- | ---------- | --------- |
| **蓄力型** | 长按到目标区间松手  | 热锅、预热、点火  |
| **节奏型** | 按节拍连续点击    | 翻炒、搅拌、打发  |
| **窗口型** | 在提示圈内按键    | 下料、翻面、出锅  |
| **维持型** | 长按并微调，抵抗扰动 | 蒸、炖、控温    |
| **顺序型** | 按正确次序按键    | 投料顺序、调味顺序 |

**[建议值] 判定参数**（含 SAN 影响，见 §6）：

| 判定      | 窗口宽度（基准） | 分数权重    |
| ------- | -------- | ------- |
| Perfect | ±60ms    | 1.0     |
| Good    | ±140ms   | 0.6     |
| Miss    | 其余       | 0（或小惩罚） |

### 4.4 其他处理方式

| 处理            | 效果                     |
| ------------- | ---------------------- |
| **淀粉糊化（勾芡）**  | 搭配度 ↑                  |
| **发酵**        | 酸 ++、鲜 ++、苦 +；带来“复杂香气” |
| **氧化**（切开后久置） | 苦 +、涩 +、鲜 −、甜 −        |

### 4.5 双菜并发（分心调度）

- 玩家可**同时做两道菜** → 两个 QTE 同时出现，可能**冲键**。
- **主菜用 WASD，附菜用方向键**。
- 设计意图：制造“手忙脚乱”的紧张感与操作上限，是高手与新手的分水岭。

### 4.6 摆盘

- **纯自由发挥**：只要不倒出去就 OK，**不加分、不扣分**。
- 定位：表达欲 / 社交分享 / 截图乐趣（拍照系统可作为后续扩展）。

## 6. SAN 值系统（克苏鲁底色）

**SAN ∈ [0, 100]**。

| SAN 区间   | 效果                                   |
| -------- | ------------------------------------ |
| 高（> 60）  | 正常                                   |
| 中（30–60） | QTE 判定窗口缩小                           |
| 低（< 30）  | QTE 明显更难；**perfect 后可能产出某道菜的“阴暗版本”** |

**判定窗口缩放**：

```
窗口实际宽度 = 基准宽度 × (0.6 + 0.4 · SAN/100)
```

（SAN=100 → ×1.0；SAN=0 → ×0.6）

**阴暗版本**：低 SAN 下打出 perfect，有一定概率得到“阴暗菜”，如
“草莓麻婆豆腐饺子”“仰望星空”等 → **解锁低 SAN 食谱**。

## 7. 客人系统

### 7.1 普通 NPC

- **点菜时会声明要求**：口味 / 温度 / 食材 / 工序 / 口感 / 香味。

- **未声明的项 = 无要求，不扣分**。

- 例（最挑剔的单）：
  
  > “一份**甜口、热的**西红柿炒鸡蛋，西红柿要**大块**（细碎度不能太高），鸡蛋要**嫩**（炒的时间不能太长），要有**西红柿本身的香味**（要求大火快炒 / 西红柿品质高）。”

**NPC 属性**：

- **消费水准**（决定出价与小费）
- **口味偏好 / “爱好”**：偏爱某地菜系或某种口味
- 高消费 NPC：更可能点**菜单里没有的菜**（不点也无惩罚，只提示原材料与主要工序）；更容易**同时有多个地方菜爱好**；更容易进高端店。
- 低消费 NPC：**很容易被价格劝退**。

### 7.2 特殊 NPC

- 触发**特殊事件**，给予**特殊奖励**（稀有食材、食谱、装修、剧情）。
- 出现几率受**装修档次**等条件影响（见 §8.1）。

## 8. 经营系统

### 8.1 装修

- 自由设计小店装修。
- **高端装修 → 人气 ↑**，并影响**特殊 NPC 出现几率**。
- **特殊装修评价**需手动解锁（需特殊条件）。
  - 例：“**高端的装修**”→ 要求所用材料价格**最低为 xxx** → 吸引“高消费人群”，提升特殊 NPC 出现率。

### 8.2 菜谱 / 名气

- 可自行设计菜单，客人按菜单点单（偶尔点菜单外的菜）。
- **菜名各自算名气**；**小店名气 = 菜单上所有菜名气之和**。
- 自建菜谱可随分店带走。

### 8.3 定价

- 可给每道菜定价。
- **价格过高 → 人气大幅下降**；**价格低 → 人气小幅上升**。

**[建议值] 价格-人气曲线**（`P₀` 为参考价 = 食材成本 × 系数 + 菜品基础价值）：

```
r = P / P₀
若 r > 1:  ΔPop = −30 · (r − 1)          // 线性惩罚，上不封顶
若 r ≤ 1:  ΔPop = +5 · (1 − r)           // 温和奖励，封顶 +5
```

再乘以**装修乘子**与**名气乘子**得到最终人气变化。

### 8.4 厨师 PK

- 参与厨师 PK → 认识其他厨师 → **解锁新菜谱**、提高小店/菜的声望。
- 认识的厨师是**招募主厨的池子**（见 §8.5）。

### 8.5 雇人

| 岗位      | 替代玩家做什么   | 说明                |
| ------- | --------- | ----------------- |
| **打杂的** | 免去擦桌子等杂务  | 基础岗位              |
| **备菜的** | 免去切菜等备菜工序 | 中阶                |
| **主厨**  | 可**替你做菜** | 来自认识的厨师，有菜系/菜谱熟练度 |
| **店长**  | 分店管理      | 需额外薪水             |

- **熟练度**决定薪水与出菜品质。
- **主厨**：不同**菜系/菜谱**有不同基础熟练度 → 影响出菜品质。
- **全托管**：若把流程全交给厨师等，则**按能力调整总利润**并**计算恶性事件触发概率**。

### 8.6 分店

- 用经营小店得到的**金钱 + 声望**解锁新地点。
- 开分店需：设计**装修**、**食谱**、**雇佣对应厨师与工作人员**。
- 新增**店长**职位（额外薪水）。

### 8.7 世界与小镇

- 不同小镇的**建筑风格 / 文化 / 饮食偏好**不同。
- 可**雇当地厨师**，也可**带自己的厨师过去**做高端地方菜。
- 后期可做“**汉堡薯条**”“**冰淇淋**”这类全世界通吃的菜 → 开遍全球分店。
- **全球影响力**：为某一道菜积累“全世界的影响力”→ 解锁成就。

## 10. 技术实现建议（给开发者的落地清单）

> 目标：让“丰富的内容”靠**数据配置**扩展，而非写死代码。

### 10.1 架构总原则

1. **数据驱动**：食材、食谱、反应、QTE、NPC、小镇全部走**配置表**（JSON / ScriptableObject / CSV）。新增一道菜 = 加一行数据，不改代码。
2. **效果器栈（Modifier Stack）**：处理工序 = 一串 `Modifier`，对菜品属性做**顺序变换**。天然支持“玩家自由排序工序”。
3. **做菜 / 评分解耦**：做菜系统只产出物理属性；评分放客人侧（见 §3.7 原则）。
4. **统一 QTE 框架**：所有 QTE 实现同一接口 `IQTE`，参数化（窗口宽度、节拍、方向、时长），便于复用与调平衡。
5. **事件与条件系统**：特殊 NPC 事件用 `flag + 条件表达式` 配置，避免硬编码剧情。
6. **数值外置**：所有 `[建议值]` 单独放 `balance.ini` / 表格，方便策划迭代。

### 10.2 建议的模块划分

| 模块               | 职责     | 关键数据                    |
| ---------------- | ------ | ----------------------- |
| `IngredientDB`   | 食材库    | 大类/小类/品质/口味/口感/香味       |
| `RecipeDB`       | 食谱库    | 必需项、理想区间、工序             |
| `CookingSession` | 单次做菜会话 | 当前菜品实例 + 工序栈            |
| `QTEController`  | QTE 判定 | 类型、窗口、分数                |
| `FlavorSolver`   | 口味矩阵求解 | 应用所有 modifier 后算最终 28 维 |
| `CustomerScorer` | 客评分    | 期望 vs 实际                |
| `EconomySystem`  | 经济     | 价格、人气、声望、金钱             |
| `StaffSystem`    | 雇人     | 岗位、熟练度、托管利润、事件概率        |
| `SANSystem`      | SAN    | 判定缩放、阴暗菜生成              |

### 10.3 关键算法草图

**A. 口味矩阵求解（伪代码）**

```
dish.flavor = zeros[7][4]
for step in orderedSteps:            // 按玩家排序
    step.apply(dish)                 // 食材 baseFlavor + 处理 modifier
applyTempEffects(dish.flavor, dish.temp)   // 温度放大/抑制表
applyTimeEffects(dish.flavor, step.time)   // 前味↓余味↑
clamp(dish.flavor, 0, 100)
dish.dominant = argmax(dish.flavor[:][主味])
dish.compound = 第二高且 > θ_compound
```

**B. 完成度**

```
Q = 100 · Σ(w_i · q_i)/Σ w_i          // q_i 为各工序 QTE 得分 ∈[0,1]
Q += qualityBonus                      // 优品食材 +5
Q -= 3 · extraSteps                     // 多余工序/食材
if missingRequired: Q *= 0.4            // 缺失必需项
Q = clamp(Q, 0, 100)
```

**C. 搭配度**

```
H = tierScore(flavorPairing)            // 相生相克 → 5 档 → {20,40,60,80,100}
  + aromaBonus + textureBonus + starchBonus
H = clamp(H, 0, 100)
```

**D. 口味搭配关系（相生相克 → 5 档）**

- 借鉴中药“相生相克”，先定义**基础关系对**（少量，如 甜×鲜=生、酸×苦=克…），
- 再对所有并存味对**求和归类**，从好到差映射到 **5 档** → 搭配度基础分。
- 好处：规则数量可控、可解释、易调平衡。

### 10.4 开发优先级（MVP → 扩展）

| 阶段           | 目标       | 内容                                       |
| ------------ | -------- | ---------------------------------------- |
| **P0 原型**    | 验证“做菜手感” | 切菜节奏 + 一种加热 QTE + 口味矩阵 + 完成度/搭配度 + 单客人评分 |
| **P1 可玩循环**  | 单店可玩     | 接单队列、自由工序、定价、人气、日循环、5–8 道食谱              |
| **P2 内容填充**  | 留住玩家     | 特殊 NPC 事件、装修、雇人、厨师 PK、野采、报刊亭             |
| **P3 经营扩张**  | 中期目标     | 分店、店长、多镇文化、自建食谱导入分店                      |
| **P4 主线与野心** | 长期目标     | SAN 系统、阴暗食谱、低 SAN 主线小镇、全球影响力成就           |

## 11. 术语表（便于团队对齐）

| 术语           | 含义                           |
| ------------ | ---------------------------- |
| 主导味          | 主味槽中强度最高的味（如“甜口”）            |
| 复合味          | 主味槽中第二高且过阈值的味（如“鲜甜口”），不覆盖主导味 |
| 细碎度 fine     | 切菜累计的破碎度，提升前味突出度             |
| 完成度 Q        | QTE 表现决定的基础品质分               |
| 搭配度 H        | 口味/香味/口感组合的品质分               |
| 效果器 Modifier | 一次处理对菜品属性的变换                 |
| 阴暗菜          | 低 SAN 下 perfect 产出的异常变体      |
