# 做菜操作 · 电脑端流程细化版（PC / 键鼠）

> 定位：**不是纯音游，而是"卡拍的做菜模拟"**。
> 所有操作建立在做菜 BGM 的节拍上；以**键盘输入 + 鼠标拖拽/点击**为主；判定偏宽松，失误只降分不判负。
> 本文件把每个操作写成**标准模块**（界面 / 输入 / 节拍规则 / 判定 / 数据产出 / 失败），并给出**节拍表（Beat Sheet）**的排布模型。

---

## 1. 总体框架

### 1.1 做菜节拍（Beat System）

- 全游戏有**做菜 BGM**，固定 BPM。默认 **120**（简单菜 90，高难菜 150）。
- 时间换算：**1 拍 = 60/BPM 秒**（120 BPM → 0.5 s）；**1 小节 = 4 拍 = 2 s**。
- **节拍可视化**：屏幕底部一条**节拍条**，一个光点随 BGM 从左向右走；每拍到达刻度线时**闪一下**，每小节第一拍（强拍）**加粗、闪金黄色**。
- **铁律**：所有做菜操作都要"卡拍"。偏差超过判定窗 = Miss / 降档。

```
节拍条（底部）
 ├───●─────┬─────┬─────┬─────┤
       ↑强拍    ↑拍    ↑拍    ↑拍
     （金光）  （白）  （白）  （白）
```

### 1.2 触发做菜

- 角色走到**功能位**（砧板 / 灶台 / 蒸笼）→ 位置上方浮现 `[E] 开始`。
- 按 **E** → 镜头拉近，进入该工序的操作界面。
- 若身上挂着订单 → 自动加载对应**菜谱 + 食材**；否则进入自由做菜。
- 进入时的第一拍为**起始拍**，所有后续节拍以它对齐。

### 1.3 三种菜式（操作集合不同）

| 菜式         | 触发点    | 包含的操作模块                                                            |
| ---------- | ------ | ------------------------------------------------------------------ |
| **切菜（备菜）** | 砧板     | M1 切菜                                                              |
| **炒菜**     | 灶台（炒锅） | M2 热锅点火 → M3 翻炒搅拌（下油/下料）→ **M3 ∥ M4 并行** → M6 顺序调味 → M3 勾芡 → M7 出锅 |
| **蒸菜**     | 蒸笼     | M1 切菜 → M6 顺序调味 → M3 上笼（长按）→ M7 出锅                                 |

> 备菜（切菜）可**提前在砧板做完**，再进灶台，减少同时操作压力 —— 这是给新手的减负路径。

### 1.4 操作与节拍的排布关系（重要）

一道菜 **不按固定小节顺序执行**。正确的心智模型是：**把这道菜需要的所有操作，逐个安排进节拍**。

- 每个操作占用 **1 拍或数拍**。
- 同一拍可以安排 **多个不冲突的操作**（左右手分工，如"翻炒 + 控温"）。
- 允许 **留白拍**（空拍休息）。
- **关键操作优先落在强拍**（每小节第一拍）。

详见 §4 **节拍表（Beat Sheet）**。

## 2. 操作模块标准模板

每个模块都按同一套字段定义，便于**模块化开发与调参**：

| 字段   | 含义                    |
| ---- | --------------------- |
| 触发   | 什么时候进入这个模块            |
| 目标   | 玩家要达成什么               |
| 界面   | 屏幕上显示什么               |
| 输入   | 键鼠怎么操作                |
| 节拍规则 | 与拍点怎么对齐               |
| 判定   | 完美 / 良好 / 失败 的门槛      |
| 数据产出 | 对 口味/温度/香味/口感/完成度 的贡献 |
| 失败处理 | 失误的后果（只降分，不判负）        |
| 时长   | 占多少拍/小节               |

## 3. 操作模块详解

### M1 · 切菜（砧板）

**触发**：走到砧板，选食材，按 E。
**目标**：按节拍下刀，把食材切成菜谱要求的样子。

```
界面
        ┌───────────────┐
        │    西红柿 🍅    │  ← 食材（可旋转）
        └───────────────┘
              ▼ 刀
   ┌───────────────────────────┐
   │  ◉ ● ○ ○ ○ ○ ○ ○          │  ← 节拍环（收缩到内圈=完美时机）
   └───────────────────────────┘
   切面方向：[横切]  (A/D 切换：横 → 竖 → 斜)
   细碎度：  ▓▓▓░░░░░  3/8
   连击：    ×3
```

**输入**：

- **空格** = 下刀（节拍环缩到内圈时按）。
- **A / D** = 切换切面方向，三档循环：**横切 → 竖切 → 斜切**。方向影响切面与入味（斜切更易入味）。

**节拍规则**：每拍可切一刀。连续卡拍 = 连击。

**判定**：

| 判定      | 时间窗     | 效果                |
| ------- | ------- | ----------------- |
| Perfect | ±50 ms  | 干净利落，+1 细碎度，连击 +1 |
| Good    | ±100 ms | +1 细碎度，连击 +1      |
| Miss    | 超出 / 空按 | 切歪（空刀），连击归零       |

**数据产出**：每成功一刀 → **细碎度 +1**；细碎度高 → **前味大幅↑、余味小幅↑**。方向匹配菜谱（如"要切块"）→ 额外加成。

**切型规则**（决定形态）：

- 同方向**连切 1 刀** = 片
- 连切 **2 刀**（中途 A/D 转向）= 块 / 条
- 连切 **3 刀以上** = 丁

**失败处理**：连续 Miss → **切到手指**（扣少量时间，偶尔 −1 SAN），不做拦截。

**时长**：由菜谱决定切几刀（通常 4–12 拍）。

---

### M2 · 热锅点火（灶台，炒菜第一步）

**触发**：进入炒菜流程的第一步。
**目标**：在游标扫进"合适火力区"时点火。

```
  火力表
  ┌────────────────────────┐
  │  冷 · ▓▓▓▓░░░ · 热      │
  │        ▲游标（自动来回扫）│
  │      目标区 [████] 绿    │
  └────────────────────────┘
          空格 = 点火
```

**输入**：**空格**。

**节拍规则**：游标扫动与 BGM 同拍，扫到绿区中心时正好是强拍（可据此预判）。

**判定**：

- 绿区**中心** = Perfect（锅温理想）
- 绿区**边缘** = Good
- 区外 = Miss

**数据产出**：决定**初始锅温**。

**失败处理**：Miss → 锅太凉（后续加热要多花小节）或太热（提高焦糊风险），不判负。

**时长**：约 1 小节（2 s）。

---

### M3 · 翻炒搅拌（WASD 命令串，劲舞团式）

**触发**：下油 / 下常见调料 / 翻炒 / 搅拌 / 勾芡（**同一模块复用**）。
**目标**：按顺序输入方向命令串，最后按空格收势。

```
   指令串：  W → A → S → D → [空格]
   ┌──────────────────────────────┐
   │   W     A     S     D     ␣   │
   │   ●     ○     ○     ○     ○   │  ← 每拍点亮一个
   └──────────────────────────────┘
   连击：×4
```

**输入**：按 **W A S D** 的方向顺序逐个按，最后按 **空格**（收势/起锅动作）。

**节拍规则**：**一声拍 = 一个指令**；最后一拍必须是空格。命令串长度随菜品复杂度 **3 ~ 7** 步。

**判定**：

| 判定      | 条件           |
| ------- | ------------ |
| Perfect | 全部指令卡拍且顺序正确  |
| Good    | 错 1 个（顺序或时机） |
| Miss    | 错 ≥ 2 个      |

**数据产出**：翻炒**均匀度** → 影响**口感**与**搭配度**。

**用途细分**：

- 下油：命令串 3 步
- 下常见调料：命令串 3–4 步
- 翻炒 / 搅拌：命令串 4–6 步
- 勾芡：命令串 3 步

**失败处理**：Miss → 受热不均（口感降档），不判负。

---

### M4 · 炒制控温（鼠标拖拽 / 引力）

**触发**：与 M3 翻炒**同时进行**。
**目标**：用鼠标把受扰动漂移的游标"吸"在合适温度区。

```
        温度
   ┌──────────────────────────┐
   │   ● 游标 ← 随机漂移        │
   │        ↙扰动（火苗/油溅）   │
   │   目标区 [▓▓▓▓]           │
   └──────────────────────────┘
   鼠标：拖拽 / 靠近 → 对游标产生"引力"
```

**输入**：**鼠标**——按住拖拽，或仅仅靠近，都会对游标产生**引力**；松手则引力消失，游标被扰动带走。

**节拍规则**：扰动按小节随机出现（如每 2 拍一次），不强制卡拍，但节奏感影响稳定度。

**判定**（按**停留时间占比**）：

| 判定      | 游标停在绿区时间占比 |
| ------- | ---------- |
| Perfect | > 80%      |
| Good    | 50% ~ 80%  |
| Miss    | < 50%      |

**数据产出**：**温度**、**香味**、是否触发化学反应（美拉德 / 焦糖化 / 脂肪氧化）。

**失败处理**：Miss → 温度失控：偏冷=夹生、偏热=焦糊味（负向香味），只降分。

**时长**：主力阶段，通常 **8 小节**（16 s）。

---

### M5 · 炖煮控温（鼠标拖拽，更稳）

**触发**：炖 / 焖 / 煮类菜式。
**与 M4 的区别**：

- 游标漂移**更慢更稳**，更容易保持。
- **允许提前离开**：玩家可以去做别的（如切配菜）。
- 离开后，屏幕**边缘常驻判定条**一直显示该菜的当前状态（HUD 常驻）。

```
   常驻 HUD（离开灶台后仍在）
   ┌────────────────────────┐
   │ 炖牛肉  ▓▓▓▓▓▓░░░░  72% │  ← 实时判定条
   └────────────────────────┘
```

**数据产出 / 失败处理**：同 M4，判定更宽松。

---

### M6 · 顺序调味（材料柜，Aimlab 式）

**触发**：需要精确调味时。
**目标**：对照材料柜，按**正确顺序**点击调料。

```
   材料柜
   ┌────┬────┬────┬────┬────┐
   │ 盐 │ 糖 │ 醋 │酱油│ 油 │
   ├────┼────┼────┼────┼────┤
   │ 料酒│ 姜 │ 蒜 │ 花椒│ 葱 │
   └────┴────┴────┴────┴────┘
   需按顺序： 盐 → 糖 → 酱油
   鼠标点击；点错 = 失败
```

**输入**：**鼠标点击**对应格子（Aimlab 式：需移动准星瞄准）。

**节拍规则**：**每个调料对应一拍**，需在该拍内点中。

**判定**：

- 全对且卡拍 = Perfect
- 顺序对但时机偏 = Good
- **点错调料** = Miss（味型跑偏）

**数据产出**：决定**口味矩阵**的正确性（主导味 / 复合味）。

**失败处理**：点错 → 主导味偏移（如先放醋导致糖色发苦），不判负。

**时长**：序列长度 3–5 拍。

---

### M7 · 把握出锅（长按空格）

**触发**：菜接近完成。
**目标**：长按空格到目标区间后松手。

```
   出锅进度
   ┌──────────────────────────┐
   │  ▓▓▓▓▓▓░░░░░░░░░░         │ ← 长按空格，进度增长
   │        目标区间 [ ██ ]     │
   └──────────────────────────┘
   长按空格 → 松手
```

**输入**：**长按空格**，在进度条落到目标区间时**松手**。

**判定**：

- 松手落在区间**中心** = Perfect
- 区间内 = Good
- 过早 / 过晚 = Miss（欠火 / 过火）

**数据产出**：出锅时机 → **香味**是否达标、**温度**是否合适。

**失败处理**：Miss → 香味缺失或焦糊，只降分。

## 4. 操作的排布：节拍表（Beat Sheet）

### 4.0 前提

一道菜 **不严格按小节顺序排布操作**。正确模型是：**把这道菜需要的所有操作，逐个安排进节拍**。小节只是节拍的容器，**不再代表固定阶段**。

- 每个操作占用 **1 拍或数拍**。
- 同一拍可安排 **多个不冲突的操作**（左右手分工）。
- 允许 **留白拍**。
- **关键操作优先落强拍**。

### 4.1 节拍表的数据结构

一道菜 = 一张节拍表。

```json
{
  "dish": "干炒牛河",
  "bpm": 120,
  "beats": [
    { "t": 1, "lanes": { "hand":  { "op": "点火", "input": "Space" } } },
    { "t": 7, "lanes": { "hand":  { "op": "翻炒", "input": "W" },
                          "mouse": { "op": "控温", "input": "Mouse", "hold": true } } },
    { "t": 20, "lanes": { "hand": { "op": "出锅", "input": "Space", "hold": 2 } } }
  ]
}
```

**三种操作形态**：

| 形态           | 占拍   | 说明                |
| ------------ | ---- | ----------------- |
| **点操作 Tap**  | 1 拍  | 切一刀、点一个调料、按一次点火   |
| **持操作 Hold** | N 拍  | 控温、翻炒、长按出锅；逐拍采样判定 |
| **留白 Rest**  | ≥1 拍 | 空拍，制造呼吸与节奏感       |

**两条轨（同一拍可并行）**：`hand`（键盘）/ `mouse`（鼠标）。

### 4.2 示例：干炒牛河 节拍表（BPM 120）

| 拍     | 键盘轨（左手）          | 鼠标轨（右手）  |
| ----- | ---------------- | -------- |
| 1     | 点火 `Space`       | —        |
| 2     | 下油 `W`           | —        |
| 3     | 下油 `A`           | —        |
| 4     | 下油 `S` → `Space` | —        |
| 5     | 下料 `W`           | —        |
| 6     | 下料 `D` → `Space` | —        |
| 7     | 翻炒 `W`           | 控温（开始·持） |
| 8     | 翻炒 `S`           | 控温       |
| 9     | 翻炒 `A`           | 控温       |
| 10    | 翻炒 `D`           | 控温       |
| 11    | 翻炒 `W`           | 控温       |
| 12    | 翻炒 `S`           | 控温       |
| 13    | **留白**           | 控温       |
| 14    | —                | 调味·盐     |
| 15    | —                | 调味·酱油    |
| 16    | —                | 调味·糖     |
| 17    | 翻炒 `W`           | 控温       |
| 18    | 翻炒 `D`           | 控温       |
| 19    | 勾芡 `Space`       | —        |
| 20–21 | 出锅（长按 `Space`）   | —        |

**读法**：

- 第 7 拍起，左手和右手**同时**被占用（翻炒 + 控温）→ 这是"双手分心"的来源。
- 第 13 拍左手**留白**，让玩家喘一口气。
- 第 14–16 拍鼠标去点材料柜，控温**暂离**。

> **关键**：这里**没有"第几小节做什么"的硬性规则**。第 14 拍的调味完全可以挪到别处，只要满足菜谱要求即可 —— **排布是可配置的**。

### 4.3 三种菜式的排布差异

| 菜式  | 排布特征             |
| --- | ---------------- |
| 切菜  | 几乎全是点操作，密集单轨     |
| 炒菜  | 双轨并行，密度高，关键操作落强拍 |
| 蒸菜  | 以长持操作为主，留白多，节奏舒缓 |

### 4.4 排布设计手法

1. **留白（Rest）**：连续操作后插 1 拍空拍，制造呼吸感，也用来"报幕"下一个操作。
2. **强拍锚定**：点火、下油、出锅等关键操作放在小节第一拍（强拍），给玩家稳定期待。
3. **密度曲线**：全曲密度不必均匀，通常**前缓后急**——越接近出锅越紧张。
4. **渐强（Crescendo）**：最后几拍适当提高密度或 BPM，制造"冲刺感"。
5. **可穿插**：非关键操作（备料、调味）允许**插空**，不必与主线严格绑定。

### 4.5 难度 = 排布密度

```
难度 ≈ f( 每拍平均操作数 , 并行轨数 , 持操作数量 , BPM )
```

- 新手菜：单轨、多留白、BPM 低。
- 大师菜：双轨、少留白、BPM 高、关键操作叠在强拍。

### 4.6 切菜 / 蒸菜的节拍表特征

- **切菜**：`[切, 切, 切, 切, 留白, 切, 切]` —— 一串点操作（密集单轨）。
- **蒸菜**：`[调味, 上笼(hold 8 拍), 留白…, 出锅(hold 2 拍)]` —— 长持操作 + 大段留白。

### 4.7 新手减负路径

可先在**砧板**把配菜切好，再上灶台 → 避免"翻炒 + 控温 + 切菜"三重并行。

## 5. 双菜并发（两口锅同时开工）

**触发**：玩家同时做两道菜（如高峰时段）。

在节拍表里，双菜并发意味着**键盘轨再拆成两条**（主菜 / 附菜），鼠标轨共用：

| 轨     | 键位               | 说明                |
| ----- | ---------------- | ----------------- |
| 主菜·键盘 | **W A S D** + 空格 | 主菜翻炒指令            |
| 附菜·键盘 | **↑ ← ↓ →** + 空格 | 附菜翻炒指令            |
| 共用·鼠标 | 一个鼠标             | 对**两条控温游标同时产生引力** |

```
   主菜：W A S D ␣        附菜：↑ ← ↓ →
   ┌──────────────┐      ┌──────────────┐
   │ ●游标  目标▓▓ │      │ ●游标 目标▓▓ │
   └──────────────┘      └──────────────┘
              ▲ 同一个鼠标对两者都有引力
           → 玩家要找"折中位置"
```

**设计要点**：

- **冲键** = 按到了对方的键位集合（主菜按了方向键）→ 判 Miss。
- 鼠标控温的"一控二"是并发难度的核心：**不可能同时完美**，必须取舍。
- 风险与收益：双菜同时出品 → 双倍收入，但两菜都可能降分。

## 6. 判定与结算

### 6.1 统一判定窗（[建议值]，可调）

| 判定      | 时间窗     | 权重   |
| ------- | ------- | ---- |
| Perfect | ±50 ms  | 1.00 |
| Good    | ±100 ms | 0.60 |
| Miss    | 超出      | 0.00 |

> 比商业音游**放宽 20–40%**，保持休闲基调。

### 6.2 完成度

```
模块得分 q_m = 该模块判定加权平均          ∈ [0,1]
完成度 Q     = 100 * Σ(w_m * q_m) / Σ w_m   （w_m 为模块权重）
```

模块权重 [建议值]：热锅 0.1 / 翻炒 0.25 / 控温 0.3 / 调味 0.2 / 出锅 0.15。

再叠加修正：食材品质加成、多余工序惩罚、缺失必需项重罚（见主大纲 §3.6）。

### 6.3 味型 / 温度 / 口感的数据流向

| 模块      | 主要影响           |
| ------- | -------------- |
| M1 切菜   | 细碎度 → 前味/余味    |
| M2 热锅点火 | 初始温度           |
| M3 翻炒搅拌 | 口感 / 搭配度       |
| M4 炒制控温 | 温度 / 香味 / 化学反应 |
| M6 顺序调味 | 口味矩阵（主导味/复合味）  |
| M7 出锅   | 香味 / 温度        |

## 8. 开发落地建议

1. **模块化**：把 M1–M7 各做成一个**可插拔组件**，实现统一接口：
   
   ```
   interface CookingModule {
     start(ctx): void
     onInput(input): void
     onBeat(beatIndex): void
     score(): number      // 0..1
     produce(): DishDelta // 对菜属性的贡献
     end(): void
   }
   ```

2. **节拍表驱动**：一道菜 = 一张 `BeatSheet`（见 §4.1），每个节拍槽挂一个模块操作。**流程不再是硬编码的顺序，而是数据**。

3. **节拍总线**：全局一个 `BeatClock`，广播拍点事件，所有模块订阅，保证严格对齐。

4. **难度即参数**：难度 = BPM + 命令串长度 + 游标扰动频率 + 并行轨数 + 判定窗倍率，全部走配置。

5. **先做三件**：① 节拍总线 ② M3 翻炒搅拌（最通用） ③ M4 鼠标控温（最能体现"PC 键鼠"特色）。

6. **可访问性**：提供"节拍辅助（判定窗 ×1.5）""自动控温（恒温箱道具）"等开关，照顾手残玩家。
