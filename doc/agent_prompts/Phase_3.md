## 1. 阶段定位

来源是大纲 §2、§7、§8.1、§8.5–8.7，以及 D021–D026。

目标是在 Phase 1 做菜和 Phase 2 营业之上，接通可走动的小镇、斜角餐厅、实体客人、客流竞争、营业时间、员工和一家后台分店。

## 2. 已完成实施顺序

### 3A｜小镇和餐厅空间

1. 小镇从中心道路生成，功能区和市场占多格。
2. 主店位于中心路口旁，支持不同占地和对应店内面积。
3. 餐厅使用斜角投影，逻辑寻路仍是四方向网格。
4. 玩家可从小镇进入餐厅，从餐厅进入后厨，也可观察另一场景。

### 3B｜客流和竞争

1. NPC 具有预算、文化偏好、装修期待、菜品期待和口碑偏好。
2. 竞品和本店按单菜竞争优势比较。
3. 装修、价格、名气、功能区和当地文化进入客流报告。
4. 进货支持延迟、市场距离、设备保鲜和按菜/单项备料。

### 3C｜实体服务流程

1. 客人依次经过迎宾、点单、入座、等菜、吃饭、收银、评价和离开。
2. 餐厅和后厨使用同一张客单。
3. 做好菜先进入传菜口；玩家或传菜员端到对应座位。
4. 超时、错菜、失败菜和重复送达都有明确终态。

### 3D｜时间、SAN 和功能区

1. 玩家设置开门和收摊，早餐、午餐、晚餐和夜宵影响客群。
2. 备货、收拾、整理、工作和休息消耗或恢复游戏小时和 SAN。
3. SAN 窗口按大纲公式缩放；异常视觉不改真实判定。
4. 功能区可互动并改变人数、预算或文化偏好。

### 3E｜面积、员工和分店

1. 餐厅占地改变维护费和室内格数。
2. 历史实现包含迎宾、收银、保洁、传菜、备菜、主厨和店长。
3. 员工工资、情绪、性格、熟练度、品质和事故进入规则。
4. 同时只开一家后台分店；菜单、员工、库存和日结独立，资金与已学食谱共享。
5. 分店同日重复结算不能重复赚钱或重抽事件。

## 3. 1013 会议产生的待替换规则

下面不是 Phase 3 未完成，而是 Phase 4 的明确迁移：

- 出锅概率阴暗菜 → 入锅时更换食材和 QTE，80 分以上才得到阴暗菜；
- 七个历史岗位 → 服务员、厨师、店长；
- 总体评价 60 分直接学菜 → 点亮、研发、80 分解锁；
- 普通做菜持续 QTE → 同菜做满 6 次后取消；
- 固定市场和功能区互动 → 玩家设置市场并划定市政功能区；
- 普通菜单外点单 → 主要按菜单点菜，少量需求只提供研发点亮；
- 低 SAN 主线 → 后期可选重演内容。

Phase 4 合并前，旧规则仍是运行事实。更新时必须同时改契约、测试、迁移和玩家提示，不能只改文档。
