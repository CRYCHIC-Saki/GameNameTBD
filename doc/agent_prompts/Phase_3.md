# Phase 3｜完整体验样板

现在执行 Phase 3：可展示的完整体验样板。
读取总控协议、已有实现和试玩反馈，执行 Grill Me；本阶段整合并打磨，不靠扩充大量内容冒充完成度。

目标：在一小段连续体验中呈现手艺、创造、经营及低SAN反差。

Grill Me优先核实未确定的画面/视角与操作体验、展示范围，以及低SAN小样的强度和可选性。未知美术方向可先做两种小样比较，不能自行承诺最终风格已获认可。

执行内容：
1. 做出一家餐馆、一个小街区、少量可辨认的NPC和一条完整特殊NPC事件。接通进入店铺、营业、交互、结算与返回，不只制作孤立展示场景。
2. 沿用番茄炒蛋教学，以实际操作触发教学步骤；包含“细碎度不一定越高越好”的可理解失败反馈。教学完成、跳过、重试与读档状态必须一致。
3. 整合统一的像素视觉规范、字体可读性、控件主题、音效、操作反馈与音量设置；加入必要的输入重绑定、暂停、失焦处理和减少动态效果选项。
4. 加入少量真实装修操作与一个情报入口；明确其已实现效果。未实现的经营加成不能展示成已生效功能。
5. 制作隔离的低SAN实验：一种难度变化、一种阴暗菜、一段异常音画反馈。通过测试入口/独立场景或独立存档验证，不提前污染正式成长流程或强行决定主线结构。
6. 将异常视觉和真实判定分离；减少抖动设置不能改变判定正确性。做出SAN恢复或退出实验的路径，不让试玩者被困住。
7. 接入少量对应已有行为的成就，验证重复触发、读档和奖励幂等；其余成就延期。
8. 打通一条内容制作流程：增加一道使用既有机制的菜和一个简单NPC事件，原则上不改通用逻辑；新机制则允许新增代码。记录真实制作步骤，不虚构耗时或产能数据。
9. 有权限与条件时导出目标平台演示包；只能导出但不能在该平台启动时，明确区分两项结果。

验收：
- 能从新游戏完成教学、正常营业、NPC事件、自建菜谱使用和一次独立SAN实验。
- 主流程无缺失资源、卡死、不可退出界面或重复领奖。
- 提供真实截图/运行证据或标注无法取得；占位资产与最终资产分开列出。
- 制作面向陌生测试者的简短试玩脚本，记录“是否理解、哪里困惑、是否想再试”。没有真人测试就保持玩法验收待定。

禁做：批量世界扩建、五家分店、完整长篇主线及全部成就。
交付一个连续可体验的样板，而不是若干互不连通的功能演示。
