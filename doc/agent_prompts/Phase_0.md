# Phase 0｜范围对齐与最小工程

现在执行 Phase 0：范围对齐与最小 Godot 工程。
遵守项目总控协议；首次运行时把协议保存为 docs/DEVELOPMENT_PROTOCOL.md，并在不破坏已有内容的前提下将入口与关键规则合入 AGENTS.md。以后每阶段必须读取。

目标：确定首轮边界，并交付能启动、能检查的工程，不实现完整做菜系统。

先执行 Grill Me。仅核实尚未回答且影响近期实现的问题，优先考虑目标平台/操作方式、QTE期间营业时间与耐心是否流逝、首轮体验的失败压力。引擎已确定为 Godot，不重复询问。

执行内容：
1. 阅读五份资料，建立“原文支持/建议值/冲突/本阶段不做”的小型清单。
2. 特别记录：五维名称与六项属性；两套 SAN 消耗分级；高SAN正常描述与连续窗口缩放公式；低SAN可选支线与主线必经；Onboarding小镇和菜品是否在数据表中存在。不要静默统一。暂不影响工程初始化的冲突可延期到对应机制开发前解决。
3. 核实 Godot 可执行文件、版本、渲染器、导出模板及测试工具。新2D原型可优先评估 Compatibility 渲染器。记录实际选择及理由，避免预览版API与稳定版混用。
4. 建立最小入口场景、可操作的启动/退出界面和一个测试场景；至少验证一次真实场景实例化和信号交互。不要创建几十个空模块。
5. 配置 InputMap、基础显示参数、代码风格、.editorconfig、Git忽略规则及依赖版本记录。忽略 .godot/ 等缓存；不要盲目忽略需要入库的 .uid 文件或资源导入配置。不要修改全局Git配置。
6. 建立一条检查入口：导入资源 → 项目脚本/场景加载检查 → 单元/集成测试。实际开发环境用PowerShell时提供 check.ps1；选定CI环境需要shell时提供对应脚本。正确处理空格/中文路径、退出码和超时。
7. 通过隔离的故意失败用例验证检查链真的会失败，再恢复正常；零测试也必须失败。CI调用同一套检查入口；尚未运行的远程CI只标记“配置完成，未运行”。
8. 为 Phase 1–2 写出可执行任务，后续阶段只保留里程碑，不提前拆出全部世界内容。

验收：
- 工程可被锁定版本打开，入口与测试场景能运行。
- 干净工作副本可完成导入、检查和测试；无法执行的项如实标记。
- 已有至少一个真实场景集成测试，不是全套 assert(true)。
- 下一阶段需要哪些确定规则、哪些资料待补，记录明确。

禁做：经营系统、全套数据转换器、分店、完整SAN系统、正式美术量产。
完成本阶段的实际工程与检查后交付，不要只给项目目录建议。
