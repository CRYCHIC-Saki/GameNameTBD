# Phase 5｜完整成长、首发内容与食品品牌

> 当前状态：规划中；只有 Phase 4 三波完成并验收后才能开始。
>
> 总流程：`docs/FULL_IMPLEMENTATION_FLOW.md`
> AI 补充：`docs/AI_FILLED_DETAILS.md`
> 来源优先：1013 会议，其次《美食游戏设计大纲 v0.2》

## 1. 阶段目标

把 Phase 1–4 的机制连成一条从新游戏到食品品牌终局的完整体验：

`教学 → 主店营业 → 熟练与研发 → 市场/店型/市政 → 事件与人物 → 分店 → 食品品牌 → 可选低 SAN 重演`

会议明确：

- 世界观是现代；
- 主流程是解锁菜谱、做菜、经营、建设小镇和事件支线；
- 长期目标是赚钱和食品品牌；
- 低 SAN 小镇后做，用来重玩前期做菜机制。

因此本阶段不写章节式救世主线，也不把低 SAN 内容设成品牌终局的必经条件。大纲中的野采、报刊亭、特殊 NPC、装修、厨师 PK、分店、全球影响力和 SAN 反差在不冲突时继续采用。

## 2. Phase 5-0｜首发内容冻结

1. 按【AI填充细节 AI-029】建立 active 内容清单。
2. 每项标记：会议明确、大纲明确、AI 填充、历史已实现、延期或放弃。
3. 每个小镇必须有文化/市场差异、可用菜、食材来源、事件、装修方向和经营选择。
4. 每道 active 菜必须经过“内容校验 → 点亮来源 → 研发 → 菜单 → 采购 → 制作/自动制作 → 评分 → 名气”的完整链。
5. 候选资料不足的菜只留在 source 清单，不能带着缺字段进入运行时。

首发最小量用 AI-029；它不是大纲承诺的全部世界规模。

## 3. Phase 5-1｜新手引导与信息设计

### 引导

按【AI填充细节 AI-027】实现：

1. 取料、切型和固定工序；
2. 第一份订单与评价反馈；
3. 进货、菜单、定价和日结；
4. 第一次点亮和不透明研发；
5. 第一次雇人和自动化。

教学触发真实业务动作，不写一套假结算。完成、跳过、重试和读档状态一致；跳过不赠送钱、食谱或熟练次数。

### 信息可读性

- 普通 HUD 只显示当前目标、材料、客人、时间和关键反馈；
- 可展开详情显示口味、温度、香味、口感、Q/H、价格、竞争优势和来源；
- 研发失败只给方向线索，不泄露隐藏精确目标；
- 市场和日结要能解释“为什么贵、为什么品质下降、为什么客人没来”。

### 设置

补齐主音量、音乐、音效、输入重绑定、窗口/全屏、暂停、失焦和减少动态效果。视觉异常设置不能改变真实判定。

### 摆盘和拍照

按【AI填充细节 AI-033】接回盘内自由摆放和本地截图。摆盘不改口味、Q/H 或客人分数；不恢复拖盘改属性、返工或联网分享。

## 4. Phase 5-2｜食材收集与报刊亭

### 三种来源

1. 采购：标准稳定供给，受市场和事件影响；
2. 野采：地图指定区域的稀有或当地材料；
3. 事件：特殊 NPC、节日、PK 和支线奖励。

按【AI填充细节 AI-021】：

- 每个首发小镇先做一个野采区；
- 每个点每天最多采一次；
- 报刊亭每天给市场波动、事件预警、稀有食材或 PK 线索；
- 情报只揭示已有状态，不能因为打开界面改变随机结果。

验收包括采集刷新、背包/仓库容量、跨日、读档、防重复领取和无用途材料检查。

## 5. Phase 5-3｜装修、店型与小镇建设

### 装修

按大纲 §8.1 和【AI填充细节 AI-023】实现格子摆放、旋转、收回、路径保护、统一度、高端度和特殊装修评价。

- 不能堵住门、收银、传菜口或全部座位；
- 店型不兼容的装修不能放置；
- 高端度影响高消费与特殊 NPC，统一度反映文化风格匹配；
- 占位外观与最终资产分开列出。

### 店型

日料、烧烤、火锅、小摊的限制和加成必须作用于：

- 可上架菜谱；
- 可用装修；
- 客群和客单；
- 员工适配；
- 成本或产出。

四种首版产出差异按【AI填充细节 AI-034】验收，不能只在界面显示一个标签。

### 市政

将 Phase 4 划区扩展为可保存的建设流程：

- 选择合法地块；
- 显示费用、耗时、预期 BUFF；
- 建设占用活动时间；
- 完成后才改变客流；
- 拆除和改建按【AI填充细节 AI-035】占时、退款并切换 BUFF。

## 6. Phase 5-4｜特殊 NPC、厨师 PK、节日与事件

按大纲 §7.2、§8.4、【AI填充细节 AI-022】和【AI填充细节 AI-032】：

1. 至少三条特殊 NPC 短事件链，每条有条件、选择、奖励和可重入状态；
2. 一条三级厨师 PK 梯度，完全复用现有做菜和评分；
3. 每个首发小镇一个节日事件；
4. 认识的厨师进入招募池，带菜系和单菜熟练度；
5. 奖励可以是食材、研发点亮、厨师资格、装修或品牌资源。
6. 特殊 NPC 只用事件阶段和 0–3 级信任推进，不增加通用送礼刷好感系统。

事件配置只允许白名单条件和动作，不能执行任意脚本字符串。事件随机、奖励和失败重试必须保存；重复进入不能重复领奖。

猪瘟和禽流感继续使用同一个事件框架，但保持供货事件身份，不改成剧情反派。

## 7. Phase 5-5｜分店、品牌与全球影响力

### 分店

按【AI填充细节 AI-024】扩展到主店加最多两家后台分店：

- 共享资金、官方解锁和自建食谱库；
- 独立菜单、价格、店型、装修、员工、库存、市场和结算；
- 店长缺失、缺货、工资不足、文化不适配和供货事件都要进入报告；
- 同店同日只结算一次；
- 不复制实时客人和 QTE 场景。

### 品牌

1. 菜名气来自该菜的实际评价和销量；
2. 店名气来自当前菜单菜名气及经营记录；
3. 食品品牌整合盈利店铺、招牌菜影响力、事件和成就；
4. 单菜全球影响力按各文化小镇的真实销售与评价累计，不因开店瞬间发放。

终局使用【AI填充细节 AI-025】：品牌 5 级、两家分店连续盈利、一道招牌菜达到影响力目标。阈值在内容冻结时外置并手算验证。

## 8. Phase 5-6｜完整 SAN 循环与低 SAN 重演

### 普通世界

- SAN 保持 0–100；
- 判定窗沿用大纲 `0.6 + 0.4 × SAN/100`；
- 工作、休息、功能区和事件改变 SAN；
- 低 SAN 视觉和假提示不使用业务随机，也不改变真实正确答案；
- 阴暗菜全部使用 Phase 4 的入锅变换和 80 分规则。

### 后期小镇

按【AI填充细节 AI-026】只做一个可选重演小镇：

- 品牌主流程完成后开放；
- 重新启用已经熟练菜的 QTE；
- 使用更难谱面和阴暗映射，但不改普通小镇的熟练自动制作；
- 可以退出并回到正常经营；
- 奖励阴暗食谱、品牌展示品或成就，不阻塞食品品牌终局。

大纲列出的多个地区阴暗菜保留为后续内容候选，不在首发一次量产。

## 9. Phase 5-7｜成就、内容生产和完整通关

### 成就

按【AI填充细节 AI-028】只接稳定业务事件。计数、条件、完成和领奖分开保存；“全成就”不能把自己当先决条件。

### 内容生产流程

新增一道正式菜必须依次完成：

1. 来源和稳定 ID；
2. 食材、替代、调料、店型和文化；
3. 固定普通谱、研发谱、评分目标和可选阴暗映射；
4. 研发图位置和点数；
5. 市场供应和价格；
6. NPC/菜单/竞品；
7. 自动测试、真实场景和试玩；
8. active 清单。

新增一个小镇必须完成市场、功能区、文化、客群、事件、野采、装修和分店模拟，不能复制改名冒充新文化。

### 完整通关

- 新档无需开发者改存档即可到食品品牌终局；
- 关键状态都能中断、保存、重载和继续；
- 另测可选低 SAN 路径；
- 至少一次真人全流程试玩，记录重复劳动、研发理解、经营选择和目标可读性；
- 模拟通关不能替代真人通关。

## 10. Phase 5 验收

自动验收：

- active 内容 ID、引用、路径、图前置和事件条件全部合法；
- 不存在不可达研发节点、必经环、重复奖励或无法完成终局；
- 市场、事件、分店和员工随机读档不重抽；
- 世界存档迁移、中断恢复和未知版本拒绝；
- 菜谱、调料、店型、装修、市场和文化组合可解释；
- 三个小镇、主店和两家分店可固定条件模拟至少 30 天；
- 品牌终局和低 SAN 可选路径彼此独立。

人工验收：

- 新玩家能否完成 AI-027 引导；
- 熟练后是否减少重复，而研发是否仍有手艺感；
- 市场、店型、市政和员工是否形成经营选择；
- 事件和现代世界观是否轻松，低 SAN 是否只是低频反差；
- 食品品牌目标是否清楚且值得继续。

## 12. 禁做和停止

首发不承诺：

- 全部 75 镇和 217 道菜；
- 大纲列出的全部低 SAN 城市；
- 每家分店实时模拟；
- 联机、账号、移动端或玩家内容平台；
- 长篇必经剧情。

达到品牌终局、内容冻结和明确试玩状态后停止新增大系统，转入 Phase 6。
