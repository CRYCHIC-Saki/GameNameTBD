# Phase 5｜完整成长流程与内容生产

现在执行 Phase 5：首发范围内的完整成长流程。
读取总控协议、全部设计资料、既有工程与阶段反馈，执行 Grill Me。

目标：把已验证系统连成从新游戏到约定终局的完整体验；不是承诺做完资料库中的一切。

Grill Me优先解决尚未确定的首发小镇/菜谱范围、低SAN主线或支线的定位、终局条件。已确认事项不重问。

执行内容：
1. 先建立首发功能/内容清单与原设计追踪表，每项标注本版实现、简化、延期或放弃及依据。特别覆盖尚未完成的装修、野采、报刊亭、厨师PK、处理反应、其余QTE、双菜并发和节日；不得默默漏掉后宣布“整个设计已完成”。
2. 按完整章节/小镇交付：进入条件、人物事件、菜品、食材来源、经营特点、奖励与后续目标连通后，再制作下一块内容。
3. 完成确认范围内的SAN升降、恢复、判定变化、阴暗菜生成、持续状态和相关事件。明确区分当前SAN、菜品Tier、SAN消耗量和生成阴暗版本的概率。
4. 解决此前记录的SAN公式/分级/主支线冲突后再实现正式流程；正式解锁顺序按已确认设计，不因Phase3曾有测试入口就提前开放。
5. 实现可审核的条件、事件和奖励配置，使用有限白名单条件/动作，不对数据执行任意代码。事件可重入、奖励不可重复领取；任务完成与领奖状态均可保存。
6. 检查推进条件引用、不可满足门槛和必经依赖环；重复日常事件与主线前置图分别处理。提供关键章节测试存档及仅开发版本可用的跳转入口。
7. 扩展融合创作、配方传播和世界影响力，复用已有配方版本及分店能力，不在终局突然替换核心系统。
8. 成就基于稳定业务事件和可保存计数，明确“所有食谱/所有成就”只针对约定内容集合，“全成就”不得把自己当作先决条件。未达开放条件的成就不能提前发放。
9. 若首发店铺/内容规模不足以支持原文的5家店、10道阴暗菜等条件，明确延期该成就或请求确认调整，不悄悄改阈值使测试通过。
10. 检查文案、占位数值与来源；保持“玩菜的梗，不嘲讽地方的人”。记录待补资产和内容，不以复制小镇充当新文化体验。

验收：
- 新档能够推进到约定终局，无需开发者手工改存档。
- 关键章节、SAN门槛、持续状态到期、事件失败重试和奖励去重有集成测试。
- 当前启用数据的ID/引用/必填项/资源路径校验全部通过；未来候选资料不足只作待办，不误装入正式内容。
- 有完整功能覆盖表，能说明原始设计哪些已实现、哪些仍不在本版。
- 完整流程的人工试玩、难度与重复劳动评估独立记录；模拟通关不等于真人通关。

完成约定首发范围后停止新增大系统，交付可进入发布打磨的版本。
