# Phase 6｜测试、兼容与发布候选版

现在执行 Phase 6：测试、兼容与发布候选版。
读取总控协议、全部阶段报告、首发清单与已知问题，执行 Grill Me。

目标：产出可重复构建、范围明确、验证证据充分的发布候选版。本提示词授权本地打包，不授权对外发布、上传商店或推送远程仓库。

Grill Me仅处理真正未定的目标设备/性能目标、存档兼容范围和发布阻断标准；不借机重新扩大游戏设计。

执行内容：
1. 冻结主要功能。按崩溃/坏档/主线阻断、经济与进度漏洞、交互问题、视觉瑕疵分级处理缺陷，先复现再最小修复并补回归测试。
2. 运行资源导入、全量规则测试、真实场景集成、关键成长链、内容校验、存档迁移和导出检查。零测试、必测pending/skipped、运行错误和超时均不得混入通过报告。
3. 在声明支持的真实设备/系统上检查启动、全屏/窗口、分辨率、输入重绑定、音量、暂停失焦、减少动态效果、长时间营业和场景切换。仅能headless运行时，图形/音频/手感项保持未验证。
4. 检查已承诺的存档版本：缺字段、坏文件、写入中断、备份恢复、内容ID变化。旧档迁移前保留备份；未知未来版本安全拒绝。不要擅自承诺兼容所有早期原型存档。
5. 检查重复交付/日结/领奖、读档重抽收益、无限无成本配方、员工与玩家重复操作、负库存及托管收益失控等漏洞。
6. 使用真实Profiler/日志检查帧时间、加载、内存及节点数量，注明硬件、版本、场景和测量方式。优化最明显瓶颈；不得用假数据宣称达到60FPS或“零泄漏”。
7. 整理资产来源、许可证及必要署名，移除未获使用许可和未批准的占位资产；检查包内不含密钥、私有资料、真实存档、测试依赖或开发作弊入口。
8. 用锁定的编辑器版本及匹配导出模板构建发布包；记录版本号、源代码提交或工作树差异、构建步骤、文件校验值、运行依赖和已知问题。
9. 在干净工作副本复现构建；能导出不等于目标设备已启动。缺硬件、导出模板、签名或人工测试时分别标记，不造证据。
10. 输出发布说明、玩家操作说明、支持平台与限制、存档兼容策略和回退方案。回退可能无法读取升级后的存档时必须说明，不能承诺一键无损回滚。

验收：
- 首发范围内无已知坏档、主线阻断及严重经济漏洞；其余问题有等级与处置决定。
- 约定支持环境的关键流程已实际验证；未验证环境不能宣传为受支持。
- 构建过程可重做，发布包资源完整，存档策略可验证。
- 最终报告分开列工程检查、目标机运行、人工玩法验收及仍需批准事项。

如果证据不足，只交付“发布候选版，尚未满足发布门槛”，不要擅自改写成“已可正式上线”。
