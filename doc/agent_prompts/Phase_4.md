## 1. 权威来源

本阶段以 `doc/source/1013会议纪要.txt` 为第一来源。会议未说明的部分，使用大纲的食材、评分、装修、定价、雇人、分店和数据驱动规则；仍不明确的部分必须引用 `【AI填充细节 AI-xxx】`。

会议明确覆盖：

- 阴暗菜在入锅时换食材和 QTE，出锅分数达到 80 才成为阴暗菜；
- 岗位只保留服务员、厨师、店长；
- 雇人和熟练度提供自动做菜，老厨师提高“做到点上”的概率；
- 同菜做满 6 次后取消普通做菜 QTE；
- 菜谱先点亮、再研发，研发达到 80 分才解锁；
- 食谱图先有中式、英式、印度三个分支；
- 玩家设置市场大小、位置、等级；本地和跨地供货有价格、品质和独有原料差异；
- 活动和事件占用时间；
- 玩家可以划定市政功能区；
- 每店独立菜单，NPC 绝大概率按菜单点菜；
- 店型是日料、烧烤、火锅、小摊；
- 调料有大类、小类和品质；地道菜要求当地调料；
- 首批供货事件是猪瘟和禽流感。

## 2. Phase 4 完成定义

玩家可以：

1. 用新版入锅规则尝试阴暗菜；
2. 把一道菜做满 6 次后跳过普通 QTE；
3. 雇服务员、厨师和店长完成真实任务；
4. 选择店型、配置市场、购买分地域和品质的调料；
5. 花点数点亮食谱节点，进行不透明研发并解锁；
6. 划定功能区并处理猪瘟/禽流感；
7. 只把已解锁且兼容店型的菜放上菜单；
8. 看见 NPC 按单菜竞争优势选择店铺。

这八项必须接到当前小镇、餐厅、后厨、库存和日结，不接受孤立演示。

3. 能运行时先执行各线套件和全量检查；不能运行时保持 `NOT_RUN`。

- AI-010 的活动令牌；

先写失败测试，再写实现。旧档和真实玩家档只读；迁移测试在隔离目录。

## 4. 第一波｜入锅变换、三岗位、调料和店型规则

### 4-1A 做菜与研发

1. 新建通用变体选择规则，不按番茄炒蛋写分支。
2. SAN `< 30` 且有显式映射时，在整锅第一次开始加工时选择阴暗食材和谱面。
3. 制作中订单和界面仍显示原菜名。
4. 最终 `≥ 80` 原子替换为阴暗菜并解锁一次；低于 80 按 AI-007 返回原菜。
5. 移除生产路径的出锅随机变菜；视觉随机与业务随机继续隔离。

### 4-1B 经济与供货

1. 扩展食材定义：调料大类、小类、品质、地域标签。
2. 食谱可以要求大类、指定小类或地域真实性。
3. 按 AI-013 选择默认调料、同类替代和品质加成。
4. 建立四种店型配置：允许菜系、工序、装修标签，并按 AI-034 实现首版产出差异。
5. 只实现规则和校验；玩家选店按钮在第二波合并。

### 4-1C 小镇与事件

1. 玩家雇佣入口只显示服务员、厨师、店长。
2. 按 AI-008 合并旧岗位职责、工资和存量员工。
3. 服务员仍真实执行迎宾、收银、保洁、传菜；厨师仍真实执行备菜和出菜；店长管理后台分店。
4. 员工和玩家不能同时占用同一工序或客单。
5. 接入 AI-010 的活动令牌，拒绝重叠的备货、休息、研发、建设和事件。

### 第一波合并验收

- SAN 低时入锅立刻切换谱，79 分原菜、80 分阴暗菜；
- 出锅不再掷变体概率；
- 雇佣列表只有三个岗位，旧职责没有消失；
- 广式要求缺广东醋时不能得到“地道”标签；
- 坏调料和店型引用在加载阶段失败；
- 重复入锅、结果读取、迁移和雇佣不重复发奖励或扣钱。

## 5. 第二波｜熟练、研发、自动做菜、市场、市政和事件

### 4-2A 做菜与研发

1. 按 AI-002 记录每道菜的玩家合法完成次数。
2. 第 6 份完成后标记熟练；第 7 次按 AI-003 自动推进固定程序。
3. 实现独立研发会话，不复用普通营业订单冒充研发。
4. 研发隐藏精确油量、火候等目标，只给方向性失败反馈。
5. 按 AI-004 消耗原料和时间；79 分不解锁，80 分原子解锁。
6. 厨师自动做菜使用真实库存、固定程序和评分；按 AI-009 处理老厨师。

### 4-2B 经济与供货

1. 市场保存大小、地图位置、等级、文化、本地原料和供应目录。
2. 按 AI-011 计算距离、价格波动和品质。
3. 按 AI-012 处理本地独有原料、跨镇运输和到货日。
4. 按菜进货继续存在；报价展开到真实原料，不产生免费的隐藏材料。
5. 固定种子和已保存报价可重现；读档不刷新低价。

### 4-2C 小镇与事件

1. 接入店型选择和 AI-014 的一次免费迁移。
2. 实现 AI-017 的可划地块、区域类型、路径保护和递减加成。
3. 实现 AI-018 的猪瘟和禽流感。
4. 事件占用一天，影响对应原料报价和品质；不能重叠或读档重抽。

### 第二波合并验收

- 熟练计数的成功、失败、员工代做和研发口径正确；
- 无 QTE 普通制作仍受食材、温度、等待和缺项影响；
- 研发提示可让玩家推断方向，且不能保存成绩刷解锁；
- 老厨师只影响自动制作，玩家判定窗不变；
- 远市场更贵且品质更低，市场升级产生可解释变化；
- 划区不覆盖道路/建筑，事件实际占时并进入存档。

## 6. 第三波｜食谱图、点数、菜单和竞争

### 4-3A 食谱图

1. 按 AI-020 做中式、英式、印度各 4 个节点。
2. 节点声明前置、主料标签、工序标签、点亮费和内容来源。
3. 按 AI-005 计算共享主料/工序折扣，最低费不越界。
4. 防止不可达节点、环、重复 ID 和未来内容误装入 active 清单。

### 4-3B 点数和状态

1. 做好菜和品牌升级按 AI-005 发点，奖励幂等。
2. 花点只把 `HIDDEN`/候选节点改成可研发，不直接解锁。
3. 按 AI-006 保留自建食谱，不用自建高分跳过官方研发。
4. 世界存档保存点数、节点、线索、研发结果、解锁和熟练度。

### 4-3C 菜单和 NPC

1. 每店一份独立菜单，只接受已解锁且店型兼容的菜。
2. 按 AI-015 让绝大多数客人从菜单点菜。
3. 菜单外互动只点亮一个相邻节点并结束需求，不生成不可能完成的订单。
4. 按会议公式和 AI-016 比较“店 × 菜”，保存 NPC 选店快照。
5. 同一 NPC、同一时刻重复查询不能改变选择或重复生成客人。

### 第三波合并验收

- 未点亮不能研发，点亮后仍不能上菜单；
- 研发 80 分后才能上菜单；
- 相近节点费用更低且理由可显示；
- 菜单内点单达到配置比例，菜单外只提供研发线索；
- 竞争优势由菜品、装修、品牌三部分组成，平局稳定；
- 旧已解锁菜和合法自建菜不丢失。

1. 三岗位和自动服务；
2. 低 SAN 入锅变换；
3. 六次熟练和第七次无 QTE；
4. 不透明研发；
5. 市场、店型、市政、事件、菜单外点亮和菜单内点单。
