# Phase 2｜单店最小可玩版

现在执行 Phase 2：单店连续营业的最小可玩版本。
读取总控协议、当前工程与前序验收，执行 Grill Me；不要重新实现已经成立的做菜原型。

目标：打通“采购备货 → 菜单定价 → 营业接单 → 制作交付 → 日结 → 下一天”，并能保存继续。

Grill Me优先处理尚未决定的营业节奏、缺料/资金不足后的继续方式、存档时点。建议首版只保证明确的营业日边界存档，不冒充支持任意QTE现场恢复；如已决定其他方式，按已确认方案执行。

执行内容：
1. 使用5–8道经审核、复用现有操作机制的菜；逐项补齐当前运行所需数据，记录来源和建议值。不要一次导入所有小镇。
2. 为日循环和订单实现明确状态及合法转移。界面只发出意图，由规则层完成采购、消耗、交付和结算。
3. 实现采购、库存、菜单、定价、耐心、客人评价、日结以及实际启用的金钱/人气/声望/菜品名气字段；未启用指标明确延期，不随便合并这些概念。
4. 定义食材何时预留、实际消耗、取消释放和失败报废；缺料时整笔操作不得留下半完成状态。金钱采用统一整数最小单位并集中处理舍入。
5. 订单交付、退款和日结必须防重复：双击、重复信号、重载和重复触发不能重复发钱、扣料或推进日期。输出可核对的简明收支/库存明细。
6. 实现最简自建食谱：保存、命名、再次制作、加入菜单。保存的是食材与工序方案及版本，不是一次高分成品；改名不改变稳定ID。
7. 存档写入 user://，包含版本、必要状态及引用ID。实施临时文件、校验、备份及失败恢复策略；实际测试写入中断，不仅声称“原子写入”。损坏或未知版本不得静默覆盖为新档。
8. 编写按既定存档边界跨日运行的集成测试，并提供日结/经营调试面板。

验收：
- 新游戏能连续经营至少3个游戏日，合法存档后重启继续。
- 覆盖缺料、超时、失败、错单、库存不足、资金不足、重复交付及重复日结。
- 存读档往返后日期、金钱、库存、自建菜谱和经营指标符合约定；测试不接触真实存档。
- 能根据上一天的反馈调整菜单/备货/价格，并观察实际后果。
- 连续手工营业的疲劳与重复感记录为试玩结论，不靠机器模拟代替。

禁做：雇员、分店、大地图、全套事件、完整SAN线。
若关键可玩性尚未获得真实反馈，交付工程就绪版和具体试玩任务，不掩盖验证缺口。
