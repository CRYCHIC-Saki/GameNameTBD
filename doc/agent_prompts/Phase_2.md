## 1. 来源和目标

来源是大纲 §2、§3.6、§3.7、§7、§8.2、§8.3；1013 会议中菜单、熟练和研发的新规则由 Phase 4 接入，不回写历史验收。

目标是打通：

`采购备货 → 菜单定价 → 自动来客 → 自由备菜 → 固定程序制作 → 交付评价 → 日结 → 下一天 → 边界存档`

## 2. 实施顺序

### 2A｜营业内容

1. 使用 5–8 道经审核的菜，复用 Phase 1 机制。
2. 食材、数量、采购价、参考价和客人要求使用稳定 ID。
3. TEST_ONLY 菜和开发入口不能进入正式菜单。

### 2B｜采购、库存和实体食物

1. 采购、预留、实际消耗、释放和报废由规则层原子处理。
2. 单一冰箱允许自由取料；原料和切配品可退回并保留状态。
3. 开始加工前可逐件取回；开始加工后只能继续整锅或丢弃。
4. 未知组合走完整流程后形成失败菜，不在中途变成已知菜。

### 2C｜订单和营业时间

1. 客人自动进入只读订单队列，玩家可以乱序完成不同菜。
2. 同菜按最早订单匹配；不同口味和切型是顾客要求，不改变基础菜身份。
3. 缺料自动谢客并产生小幅负面影响；超时不删除已做食物。
4. 到点停止新客，处理剩余订单；允许售罄、取消和提前打烊。
5. QTE 期间营业时间和耐心正常流逝，主动暂停或失焦冻结。

### 2D｜评价和经济

1. 成品交付后由独立评分器计算，不在 UI 直接加钱。
2. 定价使用大纲价格—人气曲线；参考价、收入、退款和小费集中舍入。
3. 金钱、人气、菜名气和店名气分开；未启用声望不能假装已生效。
4. 重复交付、退款、日结、信号和重载都不能重复结算。

### 2E｜自建食谱

1. 保存稳定 ID、名称、版本、实际食材和固定工序方案。
2. 不保存高分、输入录像或免费成品。
3. 再次制作必须重新消耗原料和执行流程。
4. Phase 4 后，自建食谱按【AI填充细节 AI-006】与官方研发图区分。

### 2F｜存档

1. 只在筹备和日结边界保存，不恢复营业中 QTE。
2. 临时文件写入、读回校验、备份和替换必须真实测试。
3. 损坏档和未知版本安全拒绝，不静默覆盖。
4. 测试使用隔离目录，不接触真实玩家档。

### 2G｜回归和试玩

1. 自动覆盖缺料、超时、失败、错单、库存不足、资金不足、重复交付和重复日结。
2. 新档连续运行至少 3 个游戏日并合法重载。
3. 真人试玩记录压力、重复、价格理解、缺料反馈和存档边界。
