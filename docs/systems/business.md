# 单店营业：Phase 2 / D017

本阶段复用 D015/D016 烹饪，不重新实现 QTE。菜单、采购、订单、账本和存档为真实规则；没有用固定分数或自动成功替代做菜。所有新增数值标记 PROPOSED，供试玩调整。员工、分店、地图、剧情、完整 SAN 和声望成长未启用。

## 状态和钱料

`TDShopSession` 单独拥有经济状态；`snapshot()` 返回深复制。PREPARE → OPEN → DRAINING → SETTLED → 次日 PREPARE。到点停止来客，剩余顾客继续等候；无活动订单才结算。所有菜单售罄不会卡住，可提前打烊。

- 金额为整数分；数量为整数毫份，1000=1标准份；界面显示元和份。采购逐项先检查，按每项 `round(units × cents_per_portion / 1000)` 计算整数分后求和，整笔提交。缺料或资金不足无部分扣款。
- 选择“左/右锅备菜”时原子预留整份料包，并收取预付款（ASSUMPTION）。物理拿取主料时实际消耗；调料/淀粉在原烹饪模型提交时实际消耗。累计消耗去重，搬运不重复扣料。
- 料包含主料及每种柜内调料0.4份的最大预算，覆盖错料点击；有勾芡的菜另含淀粉0.1份。这是预留上限，不是每道菜都加入全部调料。终态释放未用预留；取消/超时已用料记损耗，不退回库存。
- “补齐”只购买缺少的一份预算，“再备1份”追加整份。番茄料包首次¥7.90；做完后还有未用调料，下一次补齐会较便宜。采购库存是资产增加；日结净收支不是食品毛利。
- 订单 WAITING → COOKING → SERVED，或 CANCELLED/TIMED_OUT。订单/会话/成品 ID 必须匹配；错单保留盘子；重复交付、退款、采购 token、结算和次日请求均拒绝重复变化。
- 取消/超时退预付款；低于35分自动退本单款项，小费独立记账。玩家也可在日结主动退款。所有退款仅一次。新日不会接收旧订单的成品或操作结果。

## 时间、评价与建议值

默认初始¥300、营业360秒、耐心240秒、最多3个未完成订单；基础来客间隔75秒，按人气调整。第一位顾客在开门1秒后到店。QTE中继续营业；主动暂停/失焦冻结全部游戏时钟。FullKitchen 通过注入 `time_boundary(maximum)` 在到客、营业结束、耐心到期边界分段推进，发 `time_advanced` 后先清理过期订单，再继续后面的烹饪时间，长帧不能越过超时继续扣料。

顾客要求传给真实 Lane 和独立 Scorer；只扣已声明需求，基础 Q/H 沿用 Phase1。菜谱做法被真实输入改变；不会以固定高分交付。两组客人沿用偏甜/偏鲜要求，非番茄菜移除番茄专属切型要求。

金钱、人气、每菜名气独立启用。售价比 r = 当前价/参考价，人气价格项采用大纲 §8.3 建议：r>1 时 −30(r−1)，否则 +5(1−r)；再加 (满意度−60)/20，四舍五入，最后限于0–100。菜品名气增加 round((满意度−50)/10)，下限0；店名气为当前上架菜名气之和（§8.2）。小费为 round(价格分 × max(满意度−80,0)/200)。取消/超时人气−2。

声望是独立的0值字段，`reputation_status=DEFERRED`，不冒充人气或名气。名气引流、装修系数、PK与地区解锁延期。补助默认¥100，只在第2天起的筹备阶段、现款买不起最便宜缺额料包时由玩家主动领取，每天最多一次，账本单列。

## 自建方案和存档

日结从真实成品保存食材/工序 plan，复用 `TDRecipeLibrary` 校验；名称与稳定 ID 分开，改名增加版本。下次上架后通过相同厨房、切型谱和实际 M6 材料顺序重新制作，不保存满意度、QTE成绩或随机结果。

最小支持范围：每种原菜主料1份、完整自动工序、有效备菜、每次调料/淀粉0.1份、最多3个调味音符。允许将实际错按的调料保存成下次目标谱；缺工序/完全未切/未放调料/超预算/任意重排方案明确拒绝，不静默按原菜重做。没有自由工序编辑器。自建菜仍引用已审核基础菜谱，存档未知引用拒绝。

生产存档 `user://shop-v1.json`，当前 Windows 对应 `%APPDATA%/TownDinerPhase0/shop-v1.json`。保留已有用户目录名，避免迁移真实数据。仅筹备/日结可保存；开门前自动保存筹备，点下一天先保存日结。营业中返回或关窗口都提示丢失未保存营业；不恢复现场顾客/QTE。筹备/日结变更后可手动保存。

信封版本1，payload文本及SHA256；写 `.tmp` → flush/关闭 → 读回完整验证 → 旧档改名 `.bak` → 临时文件替换主档。真实磁盘测试中断半写、临时写完、备份后替换前；测试不是断电证明，不承诺文件系统之外的原子性。坏档不会变成新档；恢复须玩家明确选有效备份/临时文件，原文件保留 `.preserved-*`。未知版本拒绝覆盖/降级。新开店覆盖现有槽位前明确确认并保留旧文件。没有通用迁移系统。
