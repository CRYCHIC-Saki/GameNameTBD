# 剧情可视化编辑器

这是 Godot 内的「剧情」工作页，播放仍使用项目锁定的 Visual Novel Engine 0.23.0。无需启动经营游戏，不读取或保存玩家进度。

## 开始使用
1. 用锁定的 Godot 4.7.2 打开 `F:/MyGameTBD/project.godot`，点击顶部 **剧情**。默认打开港口开篇；找不到时检查「项目 → 项目设置 → 插件 → 小镇剧情编辑器」已启用。界面拥挤可按 Godot 的 Ctrl+Shift+F 隐藏两侧停靠面板。
2. 左侧像 PPT 一样选择一页。点击 **插入背景** 或 **插入角色**，从缩略图中选择素材；直接拖动画面中的人物调整上下左右位置，也能拖出屏幕。右侧可换表情、输入 **0.25–5倍** 大小或移除，Esc/右键取消正在拖动的操作。画布上方的百分比只缩放编辑视图，缩小后可看到暗色画外区域；游戏实际显示范围由细框标出。人物移远后，从右侧 **本页角色（含画外）** 选回，点 **回到画面** 将人物居中，倍率保留。
3. 右侧选择说话人、输入对白，画面即时更新，无需点应用。用 **＋ 新的一页**、**复制这一页**、**删除这一页** 编排；修改一页的构图不会连带改动后页。原开篇的流程页受保护，需调整流程时打开 **高级步骤**。
4. 点击 **▶ 试玩**，或按 **Ctrl+Enter**，在独立窗口播放当前未保存草稿。可以点击对白、选择分支、体验 CG 和输入姓名；重新播放会清空本次临时状态，■停止关闭试玩窗口。
5. **Ctrl+S** 保存，填写中文交接说明：剧情名称、所属章节／段落、具体插入位置，以及可选备注。所属段落和插入位置至少填一项，不确定可以写“待定”。确认后保存为 `.txt`；原生语法和资源检查通过才会写入。

## 美术保存与交接
美术只需制作画面、台词并说明“放在哪一段”，不用设置游戏触发。例如：

- 剧情名称：老陈赠料后的第一道菜。
- 所属章节／段落：第一章 · 第一次做番茄炒蛋。
- 具体插入位置：接在老陈赠送食材之后，玩家去冰箱取料之前；播放完交还玩家操作。
- 补充备注：替换原来的这段对话；发放食材仍由程序处理。

默认保存在 `content/story/vn/scenario/drafts/`。中文说明直接附在同一份TXT开头，不需要另交说明文件；重新打开并点击保存即可查看、修改说明。AI或开发者收到文件后据此接入实际任务。涉及新导入素材时，也需要一起交付对应图片和资源登记，TXT不会打包图片。

保存本身不会启用触发、发奖励或改动正式主线。港口开篇和已登记的剧情（包括暂时停用的）只能从此保存入口另存待接入副本，原文保留，副本记录来源与版本指纹；后续由开发者合入。取消保存不写文件；弹窗尚未确认的说明会放弃。正式游戏只打包已启用登记的剧本。

## 开发者接入（美术可跳过）
1. 阅读剧本开头的交接说明，确认其位置、前后任务和奖励需求。开启 **高级步骤** 后点击 **开发接入**；原港口教学的替换仍需开发者按主线逻辑合并，不用新触发抢播原教学。
2. 填写演出名称，选择 **与人物交互／进入地点／到达任务节点**，再从中文列表选择对象。
3. 可选前置演出或前置任务。例如“进入主店餐厅”，前置“港口介绍完成”；或者直接选择“首次番茄炒蛋送到阿铃”。
4. 选择每档一次或再次交互/进入时可重播，以及完成后的效果。默认只记录完成，可让下一段演出把它选为前置；也可开放已有菜系或商路。点击 **保存触发**。
5. 重新运行游戏测试。已经运行的游戏不会热加载触发设置；导出的EXE需要重新打包。取消“在游戏中启用”并保存即可停用绑定。

原有开篇、教学和住所流程优先，新演出不会取代它们或任意跳过主线。任务节点触发在必播教学之后执行；已有存档到达过该节点且尚未观看的新演出也可触发。地点目前是主店餐厅/厨房、小屋和五个小镇的入口，不支持在地图上绘制任意触发区域。人物目前可选阿铃、老陈，在镇上或用餐时的普通交谈入口生效；送餐、结账和门口设施仍优先。

播放中冻结游戏时间和操作。已有对话、装修、菜单、研习、QTE或夜末收尾期间不会抢控制。取消不算完成；地点离开后再次进入、人物再次交谈可重试，已到达的任务节点也可在 **J任务** 中点“观看演出”重试。每段演出的解锁效果只应用一次，即使允许重播。商路效果遵守原经营边界，在筹备/日结时播放。暂不提供任意物品/金币奖励、强改原任务进度或任意功能开关。

观看进度属于当前存档；结束演出不会自动写盘，仍需睡觉或主动保存，普通退出会回到上次记录。新绑定不改玩家已有进度；改标题不改变事件身份。播放途中不支持保存VN现场。

绑定保存在 `content/story/events.json`，应与对应剧本一起提交。备份在 `.godot/td_vn_editor/trigger_backups/`。保存触发会检查前置循环、引用和外部文件修改；运行包只收录港口开篇及已启用登记的剧本，未发布草稿不进入包。

## 已支持与边界
- 默认是页缩略图＋画布，素材来自当前已登记的 VN 库。高级步骤保留原表单、排序、淡入、等待、选项、跳转及原文编辑；未知命令或解析警告会阻止保存/试玩。
- 中间是**静态构图参考**，人物的二维位置和大小与真实播放共用布局；文字框皮肤、转场、发言明暗、动画和分支效果以「试玩」为准。画布本身不生成动画。
- CG 步骤可插入现有到港、饥饿、阿铃登场三段；具体动画镜头仍在 `src/story/arrival_cutscene.tscn` 的 AnimationPlayer 中编辑。本工具不自动生成新动画或配音。
- 开篇额外保护三段 CG、命名顺序、姓名变量及末尾结束。开篇教学不允许加跳过任务交接的分支；自由分支请在新章节里编写。
- 当前原生角色库为主角、阿铃；其他既有角色和后续章节仍沿用原系统，未自动迁移。没有更改原始 DOCX、人物图或台词。

## 素材与文件
现在可直接点顶部 **导入素材**，不用手动创建 `.tres` 或填写角色ID：

1. 选择 **背景／新角色／角色新表情**；给已有角色加表情时，再选目标角色。
2. 点 **选择图片…**，选择本机PNG、JPG或WebP，查看预览并填写中文名称。
3. 点 **导入**，等待图片导入完成。默认勾选“导入后插入当前页”，也可取消勾选，只加入素材库。
4. 在画布拖动人物、选择表情，Ctrl+Enter试玩；Ctrl+S保存剧本。

右上角 **×**、底部 **取消** 或 **Esc** 可关闭导入窗口；未点击导入的内容不会入库。图片正在导入时关闭按钮暂时禁用，完成后恢复。

图片复制到 `assets/story/imported/`，原文件不修改；背景/立绘引用、角色表和Windows导出资源列表自动登记。素材名、角色名或表情名重复会提示，不自动替换旧素材。输入图按整张使用：角色宜透明背景、各表情相同画布；本轮不做拼图裁切、视频CG或音频导入。单文件上限64MB、单边8192px。导入的是剧情角色，不会自动创建小镇NPC或任务。

导入是素材库操作；撤销画布修改不会删除已入库素材。写入前备份位于 `.godot/td_vn_editor/import_backups/`，常规写入失败回滚本次修改；外部修改冲突时拒绝覆盖。不能把多文件写入宣称为断电原子事务。添加的图片、对应`.import`配置、`.tres`、角色表（新角色时）和`export_presets.cfg`应一起入库；导出白名单只开放本工具归档目录的指定类型。

以下为已有资源或高级手动接入位置：
- 原生脚本：`content/story/vn/scenario/`；不要把参考资料放这里。
- 背景引用：`content/story/vn/backgrounds/<背景ID>.tres`；可引用 `assets/` 中的图片或 AtlasTexture。
- 原生人物：`content/story/vn/config/characters/_characters.tres`；在 Inspector 配置人物 ID / 显示名。
- 立绘引用：`content/story/vn/portraits/<角色ID>/<角色ID>_base_base_<表情ID>_mid.tres`。表单会读取已登记角色和对应表情；新资源需先由 Godot 完成导入，再重新打开剧情页/剧本。
- 既有图片位置不变；新导入图片保留一份项目副本，其他地方通过原生资源引用。

未保存草稿暂存在 `.godot/td_vn_editor/recovery.json`，下次打开有 **恢复草稿** 按钮。当前保留最近一份草稿，不等同版本库；切换前会确认。保存前的旧文本保存在 `.godot/td_vn_editor/backups/`。这些属于本地缓存，不入库，不应代替提交。磁盘上的原文被其他程序修改时拒绝覆盖，可先另存草稿再人工合并。

## 布局格式与兼容
本地作者工具版本0.6.0；上游VN仍为0.23.0。页没有另建存档格式，仍写原生TXT命令，生成的画布块由 `// td_canvas_begin v1` 和 `// td_canvas_end` 标记。二维站位写入原生show/move的position字符串 `td:x:y:scale`：1280×800设计画布，水平容器中心x与容器底边y以画幅为单位，允许-10–11（0–1是屏内锚点）；等比大小为0.25–5。日常使用不用手填。旧布局无须转换；新画外/大倍率布局需使用本版播放器。编辑视图缩放10%–100%不写入剧情、不会改变成片比例。缩略图和实际播放裁去画外内容，编辑区以暗色保留，方便构图。

交接头由 `// td_handoff_begin v1` 与 `// td_handoff_end` 包围，内部每行都是 `// ` 开头的JSON注释，原生播放器跳过。schema_version=1、purpose=author_handoff；字段为稳定id、title、section、placement、notes、source_script、source_sha256。普通保存保留ID，另存副本产生新ID并记录来源；它不是游戏事件ID。未知版本、损坏或重复头会停止保存，请保留原文处理。说明和剧本复用同一文件的临时写入、备份、外部修改校验；已确认进文档的说明随撤销及草稿恢复一起保留。没有启用AI自动判断或自动插入剧情。

正式宿主的本地CharacterLayer子类解释这个位置，其余命令和状态仍由原生VN负责；旧left/right/数值横向位置继续兼容。直接用未经本项目适配的上游播放器不能识别td位置。改过布局后若要测试导出的游戏，需要重新导出；本次未改动正式剧情、未重建原有EXE。
